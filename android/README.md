# Still for Android

Firefox for Android を参考にした、スマホ向けの Still です。画面は Kotlin と Android 標準の部品で書き、ページは GeckoView（Mozilla の Firefox for Android と同じエンジン）で表示します。デスクトップ版と保存形式を共有しています。0.4.0 までは Android System WebView（Chromium）でした。

| 項目 | 内容 |
|---|---|
| 対応 OS | Android 10（API 29）以上。targetSdk 36 |
| 配布ファイル | `artifacts/StillBrowser-Android.apk`（約90MB。GeckoView のネイティブコードは 64 ビット ARM（arm64-v8a）用だけです。32 ビットだけの端末では動かず、アップデートも表示しません） |
| エンジン | GeckoView 158（`app/build.gradle.kts`）。Firefox のリリースに合わせて上げます |
| 署名 | デバッグ鍵です。Google Play で配布するには、自分のリリース鍵で署名し直す必要があります |
| iOS | 未対応です。ビルドに macOS と Xcode が必要なためです |

## 使い方

- 下部のアドレス欄に URL か検索語を入力します。URL でない文字列は、設定した検索エンジンで検索します（判定規則はデスクトップ版の `core` と同じです）。
- 入力中は、アドレス欄のすぐ上に候補を出します。入力した語をすべて含む開いているタブ（タップでそのタブに切り替え）・ブックマーク・履歴と、検索エンジンの候補（Google・Bing・DuckDuckGo。Yahoo! JAPAN は公開の候補 API がないため出ません）です。一番合うものがアドレス欄の隣に来ます。検索エンジンには入力中の文字を送るので、設定 › 検索 › 「検索候補を表示」で止められます。`https://` で始まる入力や、パスを含む URL は送りません。
- リンクを長押しすると、新しいタブで開く・リンクをコピー・共有を選べます。
- URL を表示している部分を左にスワイプすると右隣、右にスワイプすると左隣のタブに移動します。端では止まります。上にスワイプするとタブ一覧を開きます。タップすると URL を編集でき、編集中のスワイプでは何もしません。
- ツールバーのボタンは、戻る・進む・新しいタブ・タブ（開いている数）・メニューです。メニューを押すと下からシートが開き、ブックマークへの追加／削除・共有・再読み込みと、新しいタブ・ブックマーク・履歴・ダウンロード・設定を選べます。空のタブでは、ブックマーク・共有・再読み込みは使えません。シートの外側をタップするか Android の戻る操作で閉じます。
- タブボタン、またはアドレス欄の上スワイプで、画面の約9割を使うタブ一覧を開きます。ページのプレビューを格子状に並べ、選択中のタブを強調します。各カードの閉じるボタンでタブを閉じ、下部の「新しいタブ」で追加できます。プレビューはメモリ上だけに保持し、再起動後や未表示のタブには代わりの絵を表示します。
- 新しいタブには Still のロゴと、ブックマーク・よく訪れるホストから最大8件のショートカットを表示します。初回起動時のように候補がなければショートカットは表示しません。検索・URL の入力には下部のアドレス欄を使います。
- ブックマーク・履歴・ダウンロード・設定は、それぞれ独立した全画面です。上部の戻るボタン、または Android の戻る操作でページへ戻ります。
- 新規インストール時のアクセントカラーは Purple（Firefox 風のバイオレット）です。既存の保存データにある色は引き継ぎます。
- 設定には、起動時に開くもの、ホームページ、テーマ（自動／ライト／ダーク）、アクセントカラー、新しいタブの画像、検索エンジン、閲覧履歴を残すか、閲覧データの削除があります。
- 設定 › 外観 › 新しいタブの画像 の「選ぶ…」で、新しいタブの背景に好きな画像を表示できます。Android 13 以上ではシステムの写真選択画面、それより前はファイル選択画面で選びます（ストレージの権限は不要です）。PNG・JPEG・GIF・WebP・AVIF・BMP の20MBまでで、画面を覆う大きさに縮小して表示します。選んだ画像は `files/NewTab/` にコピーするので、元の画像を消しても残ります。「外す」で元の無地に戻ります。
- 他のアプリのリンクから開いたときや、共有メニューで「Still」を選んだときは、新しいタブで開きます。既定のブラウザにも設定できます。
- 設定 › 他のブラウザから引き継ぐ の「ファイルを選ぶ…」で、パソコンの Chrome・Edge・Firefox・Safari から書き出したブックマーク（HTML）か、Google データエクスポート（Takeout）の Chrome の `History.json` を取り込めます。ブックマークは今あるものの後ろに追加し、履歴は日時順に混ぜて新しい500件を残します。Android は他のアプリのデータを読ませないため、端末内の Chrome から直接は読めません。
- パスワードは Android の自動入力サービス（Google パスワードマネージャーなど）がページのログイン画面に入力します。Chrome に保存したパスワードも、同じ Google アカウントなら使えます。設定の「自動入力の設定」から開けます。パスワードの CSV を選ぶと、そのことを案内します（Still には保存しません）。
- 他のアプリの Cookie は読み取れないため、ログイン状態は引き継げません。Still でログインし直してください。
- 横画面と、幅 600dp 以上の画面では、アドレス欄とボタンを1行に並べます。

## アップデート

起動するたびに `https://still.dongurihub.com/update.json`（`site/build.py` が作るもの）を確認し、`versionCode` が今より大きい APK があれば画面上部に通知を出します。「更新」を押すと APK をダウンロードし、サイズと SHA-256 を確かめてから、システムのインストーラー（`PackageInstaller`）に渡します。設定 › 情報 › 「アップデートを確認」からも確認できます。

- 初回は「この提供元のアプリを許可」の設定画面を開きます。許可して戻ると、そのまま更新の確認画面が出ます。
- インストール済みのアプリと同じ鍵で署名した APK でないと、システムが更新を拒否します。今はデバッグ鍵で署名しているため、別の PC でビルドした APK には更新できません。
- 更新後、Still は自動では起動しません。タブ・履歴などの保存データはそのまま残ります。
- 確認先は `app/build.gradle.kts` の `update_url` です。`./gradlew assembleRelease -PstillUpdateUrl=…` でビルド時に変えられます。
- 版は Windows 版と同じで、`windows/launcher/Cargo.toml` の `version` から決まります（`versionName` はそのまま、`versionCode` は 0.5.1 なら 501）。リリースのたびにそこを上げてください。同じか小さい番号は更新として扱いません。

## デスクトップ版との違い

| 項目 | Android 版の扱い |
|---|---|
| ダウンロード | エンジンが渡すデータ（ページの Cookie 付き）を MediaStore で `Download/` に書きます。ストレージの権限は不要で、同名のファイルは上書きせず、書き終わるまでほかのアプリからは見えません。失敗した途中のファイルは削除します。アプリのプロセスが終わると中断します。保存先の変更と「毎回確認する」はありません |
| ページのダークモード | アプリのテーマ（自動／ライト／ダーク）を、どの Android の版でもページの `prefers-color-scheme` に反映します |
| サイドバー | メニューからブックマーク・履歴・ダウンロードの独立した全画面を開きます。タブはプレビュー付きの下部シートです。`Sidebar` の設定値は保存データの互換のために残しています |
| 位置情報・カメラ・マイク | 許可を求めず、すべて拒否します（アプリにその権限がありません） |
| 背景タブ | 直近に表示した4タブまでページを保持します。それより古いタブは戻る・進むの履歴を残したままページを解放し、次に表示したときに読み込み直します。メモリ不足の通知を受けたときは、表示中のタブ以外を解放します |
| ページのダイアログ | `alert`・`confirm`・`prompt`、`<select>`、日付・時刻・色の入力、HTTP 認証、ページを離れる確認、フォームの再送信、ファイルの選択、`navigator.share` を Android のダイアログで出します（`Prompts.kt`）。月・週の入力は文字で入れます |

## 安全のための動作

- `file:` と `content:` のリンクは開きません。`mailto:`・`tel:`・`intent:` などは、ユーザーが操作したときだけ外部アプリに渡します。その際、特定のコンポーネントを指定した起動はできません。
- スクリプトによるポップアップは、タップなどの操作から開かれたものだけを許可します。`window.opener` は保たれるので、ログイン用ポップアップも動きます。
- 混在コンテンツ（https のページの中の http のスクリプト）は Gecko の既定どおり遮断し、証明書エラーは Gecko のエラーページになります。トラッキング防止（GeckoView の標準設定）を有効にしています。ページとアプリをつなぐ橋渡し（拡張機能やメッセージ）はありません。
- 閲覧データ（Cookie・履歴・保存データ）は、クラウドバックアップや機種変更時のデータ転送の対象外です。
- ページのプロセスがクラッシュしても、アプリは終了しません。通知が出て、「再読み込み」で復帰します。Android がメモリ不足でページのプロセスを終わらせた場合は、通知を出さずに戻る・進むの履歴ごと読み込み直します。スクリプトが止まらなくなった場合は通知が出て、「停止」で止められます。

## データの保存

`files/state.json` に、デスクトップ版と同じ形式（PascalCase の JSON。`desktop/DESIGN.md` §5）で保存します。Android 版ではダウンロードの `Id`（負の数は MediaStore の行、正の数は 0.4.0 までの Download Manager の ID）と、設定の `SearchSuggestions` が追加されます。取り込んだブックマークの名前は `BookmarkTitles` に入ります（取り込んだときだけ書きます）。

- 保存は 0.8 秒ごとにまとめて行い、アプリが背面に回ったときにも保存します。一時ファイルに書いて同期してから置き換えるため、途中で終了しても壊れたファイルは残りません。
- 読めないファイルや、新しいバージョンが書いたファイルは、別名でのコピーが成功するまで上書きしません。

## ビルドとテスト

```sh
cd android
./gradlew testDebugUnitTest lintDebug assembleRelease    # JVM テスト61件、lint、APK（arm64）
./gradlew assembleRelease -PstillAbis=x86_64             # x86_64 エミュレーター用
python3 tests/device_check.py app/build/outputs/apk/release/app-release.apk ../artifacts/android-checks
```

`device_check.py` は、root 化されたエミュレーター（Google Play 版以外のシステムイメージ）か端末で、アドレス欄のスワイプと候補を含む23項目を確認します。`tests/site` をローカルで配信し、`adb reverse` 経由で読み込むため、外部サイトには接続しません。確認する項目は次のとおりです。
起動時間、空のタブのホーム表示、メニューの開閉と空のタブでの無効操作、URL の入力と保存、操作なしのポップアップの遮断、ライト／ダークでの `prefers-color-scheme`、リンク・戻る・履歴、ブックマーク、メニュー・一覧表示中にページがスクリーンリーダーから隠れること、`target=_blank`、`window.opener` を保つポップアップと `window.close`、`file:` の遮断、`mailto:`、ダウンロード、タブの追加と切り替え・撮影したプレビュー・選択状態、アドレス欄の候補（履歴・開いているタブ・検索エンジン）、回転時にページが保たれること、ページのプロセスが終わったときの復帰、再起動時の遅延復元とプレビューの代替表示、ホームのショートカット、新しいタブの画像（写真選択画面で選ぶ・新しいタブだけに表示・再起動後も残る・外す）、1・5・20タブでのメモリ。

結果とスクリーンショットは `artifacts/android-checks/` に出力します。今回の UI 変更では端末・エミュレーターを接続していないため、この操作確認とスクリーンショットの更新は未実施です。

## 計測結果（エミュレーター）

以下は UI 変更前に Android 15（x86_64 エミュレーター、KVM、ソフトウェア描画）、GeckoView 158、リリース APK（x86_64）で計測した参考値です。今回の UI 変更後は再計測していません。

| 指標 | 結果 | 条件 |
|---|---|---|
| コールドスタート | 中央値 約1.4秒 | `am start -W` の TotalTime、5回、空のセッション |
| メモリ（PSS、アプリと GeckoView の全プロセスの合計） | 1タブ 約380MB → 5タブ 約360MB → 20タブ 約500MB | 軽量なローカルページ、各タブを開いてから 1.5〜4.5 秒後 |

エミュレーターでの値なので、実機の性能を表すものではありません。WebView 版（0.4.0：1タブ 約89MB）より大きいのは、WebView は Android 側で共有される部分が計上されにくいのに対し、GeckoView はエンジン全体（GPU・ページ用のプロセスを含む）をアプリが持つためです。背景タブのページは4つまでしか保持しません。
